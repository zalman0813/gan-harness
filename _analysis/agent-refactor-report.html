對照 Anthropic 三條原則

① Attention budget / context rot
As the number of tokens in the context window increases, the model's ability to accurately recall information from that context decreases. Effective context engineering for AI agents

你那句「要先用 skill」躺在第 200 行,模型早已 recall 不到。

② 最小高訊號集
Good context engineering means finding the smallest possible set of high-signal tokens that maximize the likelihood of some desired outcome. Effective context engineering for AI agents

你現在是反過來:最大低訊號集。

③ Brittle hardcoded prompt
engineers hardcoding complex, brittle logic in their prompts… creates fragility and increases maintenance complexity over time. Effective context engineering for AI agents

generator 把 deep-module shape、ADR three-test gate、inner-gate stages、next_action 三分支全 hardcode 在 body —— 這些本該 JIT 載入。

④ 工具/技能重疊 → 不知道用哪個
If a human engineer can't definitively say which tool should be used in a given situation, an AI agent can't be expected to do better. Writing effective tools for AI agents

generator-handbook 一大包 → 觸發邊界模糊 → agent 乾脆不載,自己重寫。

結論 drift 不是因為你沒下指令,是因為指令和一大包方法論搶同一個注意力預算,而方法論用體積贏了。

B診斷二

「重造輪子 / 不用 strands」是必然結果,跟 bloat 無關

這是第二個獨立問題。對 Apollo 的結構診斷發現:NEGOTIATE 的 input 清單裡完全沒有「現在已經有什麼」這一項。

完全沒讀
✕ codebase ✕ component registry ✕ 現有 strands subagent 清單 ✕ CODEMAP.md(只在 /finalize 生成)

agent 手上沒有「現有元件目錄」,reuse-vs-build 對它就是未定義的決策點。而模型訓練偏誤是 completion —— 未定義時就直接造一個新的。你 prompt 寫「要用 strands」沒用,因為它根本不知道哪個 strands 可用、長什麼樣、入口在哪。

When tools overlap in function or have a vague purpose, agents can get confused about which ones to use… Too many tools or overlapping tools can also distract agents from pursuing efficient strategies. Writing effective tools for AI agents
The agent tended to try to do too much at once—essentially to attempt to one-shot the app. Effective harnesses for long-running agents — 同一份 over-ambition 失敗模式
結論 要它 reuse,必須把「可 reuse 的東西」當成 just-in-time input 餵進去,並把 reuse 設成硬性 gate,而不是一句勸告。 → 見 Part D3。

C參考範本

GodotPrompter pattern 蒸餾 — 你要抄的 8 條

參考 agent 只有 73 行 / 785 字,卻能驅動 48 個 skill。秘訣:agent body 只放斷言 + 條件式 skill index,how-to 全在 JIT 載入的 skill。

  1. Agent body ≤ 一個螢幕(~70 行)。只留 ① identity 一句 ② modes/triggers ③ principles(斷言,非教學)④ skill index(條件式)⑤ output format。出現 >1 行 code 或 API 表 → 一律外移。
  2. Principle 是 claim,不是 tutorial。agent 說「avoid Variant boxing」,skill 才示範怎麼做。你 generator 第 162–228 行就是 tutorial 塞錯地方。
  3. 一個 skill = 一個 concern,激進地切。GodotPrompter 把「C#」拆成 csharp-godot + csharp-signals + godot-optimization。對應你說的「skill 該明確而非一大包」。
  4. skill description 一律 Use when <trigger> — <子題逗號清單>。trigger 決定何時載入,清單當 scope 圍籬。最該抄的一條。
  5. 在 agent body 用條件式明文 wire skill:Read skills/X/SKILL.md when <condition>,標一個 Primary。不是 flat frontmatter list。
  6. skill 之間用 Related skills: 橫向連結。載入的 skill 自己 route 到鄰居,agent 不必認識全部 skill。
  7. repo/workflow 專屬程序留 agent,domain 知識進 skill。GodotPrompter 把「parity mode 6 步」留 agent(專屬),domain 保持可重用。
  8. agent description 用 <example> 做 routing,skill description 做 loading。兩個不同受眾:dispatcher 選 agent vs agent 選 skill。
Anthropic 背書 這正是 Agent Skills 的 progressive disclosure:metadata 永遠載入 → body 觸發時載入 → bundled files 按需載入。

D3 · 修掉 reuse drift(Part B 的解,最重要)

(a) 給它「現有什麼」的 JIT input

NEGOTIATE input 清單加第 8 項:

Component/strands registry — read CODEMAP.md (or a /loop-time component-inventory) listing existing modules + reusable strands subagents with their entry points.

CODEMAP.md 現在只在 /finalize 生成 → /loop 期間 agent 看不到任何現有元件。要在 /loop start 就生一份輕量 inventory(路徑 + 一行用途,不塞全部 code —— 符合 Anthropic just-in-time / lightweight identifiers)。

(b) 把 reuse 設成硬 gate

contract self-check 加第 7 條:

Reuse-before-build — 每個 done_looks_like[] 若新增 module/subagent,必須註明「checked registry; no existing X covers this because <reason>」。未註明 = evaluator reject。

把「未定義決策點」變成「必須回答的問題」,擋掉 completion 偏誤。

D4 · Strands / MCP 使用準則(對應你「如有 mcp 應該要做」)

subagents… help manage context: subagents use their own isolated context windows, and only send relevant information back. Building agents with the Claude Agent SDK
MCP… handling authentication and API calls automatically… without writing custom integration code or managing OAuth flows yourself. Building agents with the Claude Agent SDK
  • 既有 strands subagent 用單一明確 tool/MCP 入口呼叫,在 agent body 一句不可誤解的契約:To run a strands agent, call <tool>; NEVER hand-roll the orchestration. — 對應 Anthropic「consolidate into few high-impact tools」「namespace」。

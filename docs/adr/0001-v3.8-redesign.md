# ADR-0001 — gan-harness v3.8: three-stage GAN loop with per-sprint contract negotiation

## Context

The v1 design used four stages (`/prd` `/plan` `/execution-loop` `/finalize`) with a granular `feature-list.json` produced at /plan that pre-coded acceptance criteria, must-not literals, and eval anchors. In practice, three failure modes surfaced:

1. **Planner over-prescription cascade.** `/plan` locked granular AC at design time; when implementation revealed a spec assumption was wrong, generator could not amend, evaluator FAILed three rounds, status flipped to `deferred`, and the human had to reconcile in /finalize retro path. Net effect: human was *not* out of the loop.

2. **`/prd` and `/plan` were two stages doing one job.** Both clarified intent and structured deliverables. The split added a transition cost without adding signal.

3. **Single evaluator with mixed cognitive modes.** Evaluator ran AC literal coverage, adversarial probes, structural review, and behavioral verification all in one prompt. The modes interfered (criticism rubric vs structural empathy vs literal grep).

Anthropic's April 2026 post [*Harness design for long-running application development*](https://www.anthropic.com/engineering/harness-design-long-running-apps) describes a three-agent harness (planner / generator / evaluator) with **per-sprint contract negotiation** that produced fully working full-stack apps over multi-hour autonomous runs. The key insight from that work, line 78:

> "Before each sprint, the generator and evaluator negotiated a sprint contract: agreeing on what 'done' looked like for that chunk of work before any code was written. This existed because the product spec was intentionally high-level, and I wanted a step to bridge the gap between user stories and testable implementation."

The v2 design's spec stays deliberately high-level; granular testable details emerge per-sprint from generator+evaluator negotiation. Implementation freedom is preserved within each sprint contract.

## Decision

Adopt a v3.8 redesign that follows Anthropic v2 fidelity for structure, with two deliberate departures motivated by gan-harness's "human out of the loop, autonomous overnight" target use:

### Three stages, three agents, one optional helper

- `/init` — planner produces immutable `specs/_epic/spec.md` (vision + features + sprint plan + 4 archetype criteria + cross-cutting + overall success + references). Default grills via AskUserQuestion; `--no-grill` bypasses.
- `/loop` — per-sprint: negotiate contract → implement → evaluate. No max round budget; operator monitors cost externally.
- `/finalize` — archive-only path. Promotes proposed ADRs, merges new domain terms into CONTEXT.md, regens CODEMAP.md, archives `specs/_epic/` → `specs/epics/<slug>/`.

Agents: `planner`, `generator`, `evaluator`, plus `codebase-fact-finder` (optional helper for brownfield epics, dispatched by planner).

### Spec is high-level Markdown, immutable per epic

`specs/_epic/spec.md` is the single planning artefact. Markdown structure enforced by `spec_lint.py` L01-L07. NO granular AC. NO pre-coded test contract. NO per-sprint testable detail.

### Per-sprint contract negotiated and append-only

`specs/_epic/contracts.jsonl` is the append-only log of negotiated contracts. Schema at `.claude/schemas/contract.schema.json`. Each entry has phase: `agreed` → `completed` → optional `amended`.

### 4 evaluation criteria per archetype, globally shared

Spec.md `## Evaluation criteria` carries exactly 4 entries pulled from the archetype template (frontend / backend / library / cli / data-pipeline / hybrid). Per-sprint contracts reference them via `criterion_mapping`. Evaluator's threshold check is per-criterion: any criterion below threshold = sprint FAIL.

### Anti-drift via JSON shape + helper-script + hook-enforced immutability

- `block_pretool.py` enforces: spec.md immutable for generator/evaluator/fact-finder (only planner writes during /init); contracts.jsonl Edit/NotebookEdit always rejected (Write OK as append).
- Bash-mutation patterns targeting these paths (`>`, `sed -i`, `tee`, `mv`, `cp`) are also blocked.

### Transcript-as-evidence

SubagentStop hook captures Claude Code runtime's `transcript_path`. Evaluator reads the slice instead of any generator-authored narrative. Reasoning: the runtime cannot be lied to; the narrative can.

### Departures from Anthropic v2

1. **No escalate mechanism.** Anthropic v2 has none. gan-harness inherits this. Loop runs until evaluator approves OR operator stops based on cost. Generator's anti-oscillation rule (same finding 3 rounds in a row → MUST pivot) is prompt-level discipline, not a halt mechanism.

2. **Archetype-aware criteria.** Anthropic v2's 4 criteria (design / originality / craft / functionality) come from frontend experience and don't fit backend/lib/CLI/data epics. gan-harness picks 4 criteria from the archetype template at /init.

## Consequences

### Positive

- Human out of the loop: 0-2 checkpoints across the entire epic (vs 4-6 in v1).
- Generator has implementation freedom within sprint; evaluator negotiates the testable rubric without imposing it.
- Spec stays under 10 pages typical (vs feature-list.json bloat).
- One workflow tier removed (`/prd` + `/plan` → `/init`).
- v1 retro path eliminated; /finalize is archive-only.

### Negative

- spec_lint.py L05 (vertical-slice cross-layer) is partial — only checks pure-* tag presence, not actually verifies cross-layer coverage. Evaluator catches missing cross-layer at QA time.
- No max-rounds cap means a stuck loop costs money until operator intervenes. Anti-oscillation prompt-level rule is the soft mitigation.
- Existing in-flight epics in v1 format (specs/_batch/*) need manual migration; the rename is one-shot.
- Per-archetype criteria templates need maintenance as new archetypes emerge.

### Tradeoffs explicitly accepted

- v1's three-test ADR gate is preserved.
- v1's CONTEXT.md / CODEMAP.md / docs/adr/ keep-alive infrastructure is preserved.
- v1's deep-module-handbook is preserved and shared by all three agents.
- v1's `block_pretool.py` PreToolUse hook is preserved and extended.
- v1's `log_subagent_stop.py` SubagentStop hook is preserved and gains transcript-path capture.

## Alternatives considered

### Keep v1 and tune planner

Rejected because the over-prescription was structural. Even with a more permissive planner, the AC pre-coded in feature-list.json is read by the evaluator as the rubric — generator can't move outside it without the planner's agreement, which doesn't happen until /finalize retro.

### Adopt the older Anthropic harness (feature_list.json)

The older Anthropic harness ([Effective harnesses for long-running coding agents](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)) used a 200-feature JSON with `passes` boolean, no negotiation. JSON anti-drift property is attractive but the absence of negotiation reproduces v1's over-prescription problem. The newer paper is the design we follow.

### Three-evaluator cognitive split (spec-auditor / adversarial-reviewer / journey-witness)

Considered and rejected for v3.8. Anthropic v2's empirical result is that 1 evaluator + Playwright + tuned prompt drives a real 3-hour DAW build. 3-mode split adds complexity without empirical justification. May revisit if v3.8 evaluator quality plateaus.

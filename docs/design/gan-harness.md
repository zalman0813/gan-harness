# gan-harness — PRD → Plan → Execution-loop → Finalize

Language-agnostic reference for the four-stage coding-agent harness.
The pipeline core stays language-free; framework adaptation lives in
pluggable **stack skills** (Python, FastAPI, Next.js, AWS CDK, Flutter,
etc.). This file is for harness maintainers; target projects do not
inherit it.

## Stage map

```
/prd                /plan                  /execution-loop        /finalize
  │                   │                      │                      │
  ▼                   ▼                      ▼                      ▼
specs/_batch/      specs/_batch/          per-feature             ADR proposed→accepted
  prd.md             feature-list.json     Generator↔Evaluator    Domain terms → CONTEXT.md
  research.md      docs/adr/NNNN-*.md      up to 3 rounds          codemap regen
                     (status: proposed)    state DONE/BLOCKED      archive batch
```

The four stage commands are language-neutral. Stack-specific syntax
plugs in via the active stack skill at execution time (see § Stack skill).

## Alive docs — agent-consumed at runtime

```
ARCHITECTURE.md             matklad-form invariants ("absence of X" facts)
CONTEXT.md                  Pocock-style ubiquitous language (Language /
                            Relationships / Example dialogue / Flagged
                            ambiguities). Lazy-created by /finalize on
                            first batch with Domain terms.
docs/adr/
  NNNN-<slug>.md            MADR architectural decision; status flows
                            proposed → accepted → superseded; body is
                            immutable.
  index.md                  Auto-regenerated by /finalize per batch.
app_docs/
  codemap.md                Auto-regenerated module map (barrel-file
                            docstrings extracted by regen_codemap.py).
specs/
  _batch/                   Live batch scratch:
    prd.md                  Per-batch PRD, all R as H2 sections.
    research.md             Blindfold codebase facts + base_commit + ts.
    feature-list.json       Planner output, validates against schema.
  completed/<slug>/         Archived batches (frozen historical record).
```

The codebase remains the source of truth for code (signatures, tests,
runtime behaviour). Alive docs fill what code cannot express.

## Stage 1 — /prd

Grill-driven requirements + blindfold codebase research + synth.

**Owner**: MAIN (interactive grill cannot be a subagent — `AskUserQuestion`
multi-turn dialogue belongs in MAIN; subagents are for fresh-context
bulk work).

**Internal phases** (single command, no human checkpoint between phases
except Phase 2):

```
Pre-flight   specs/_batch/ empty? abort if half-done batch present
Phase 1      Grill in MAIN (load grill-protocol.md)
Phase 2      Post-grill checkpoint — single AskUserQuestion (Approve / Revise / Abort)
Phase 3      Codebase-fact-finder × N (parallel ≤6/turn, blindfold = prd.md)
Phase 4      Synth — compile research.md, run prd_lint, delete transient
```

**Inputs**:
- `$ARGUMENTS` (free-form intent dump, optional — grill asks if empty)
- `CONTEXT.md`, `docs/adr/index.md`, `ARCHITECTURE.md`
- Active stack skill at `.claude/skills/<stack>/`

**Outputs**:
- `specs/_batch/prd.md` — per-batch PRD; H2 section per R; six required
  sub-sections per R (Problem / Solution / User Stories / Acceptance
  Criteria / Constraints / Domain terms (draft))
- `specs/_batch/research.md` — blindfold codebase facts compiled from
  fact-finder agents, with `base_commit` + `timestamp` header for rot
  tracking

Transient (created and deleted within /prd):
- `specs/_batch/_research-queue.md` — questions for fact-finder dispatch
- `specs/_batch/_research-findings/Q-NN.md` — per-fact-finder outputs

**Skill**: `prd-workflow` + `references/grill-protocol.md`.

### Grill discipline

`grill-protocol.md` codifies seven core rules — one Q at a time;
recommend before asking; **reframe vague targets as measurable success
criteria** (Addy Osmani convention); surface contradictions, don't
auto-resolve; cross-check `CONTEXT.md` for term conflicts and
`docs/adr/index.md` for ADR conflicts; codebase claims always go to
the research queue, never verified inline.

The Reframe pattern bounces "make it secure" / "make it fast" back as
concrete bullets:

```
USER: "Make password reset secure"

REFRAMED SUCCESS CRITERIA:
- Reset tokens have ≥128-bit entropy
- Tokens expire after 15 minutes (configurable)
- Tokens are single-use (consumed after first verification)
- Failed attempts logged with rate-limit trigger after 5/hour per IP
→ Are these the right targets?
```

Each reframed bullet becomes a candidate AC. Vague targets that are not
reframed become assumption debt — `prd_lint.py` cannot catch them, so
the discipline is upstream at grill time.

### prd.md structural lint (PASS/FAIL)

`scripts/prd_lint.py` runs at end of Phase 4. Six rules:

| Rule | Checks |
|---|---|
| L01 | H1 = `# Batch PRD — <kebab-slug>` |
| L02 | ≥1 `## R\d+ — <r-slug>` H2 section |
| L03 | Each R has all six sub-sections in fixed order |
| L04 | User Stories has ≥1 Cohn-form numbered line |
| L05 | Acceptance Criteria has ≥1 `- [ ]` checkbox |
| L06 | No forbidden top-level sections (Implementation Decisions / Tech Stack / Architecture / Risks / Tech Debt / Timeline) |

L06 enforces the industry convention: PRD = what/why; plan = how. The
Pocock-style content split (template-meta in stack skill, decisions in
ADR, code in code) is what keeps this clean.

### Blindfold preserved at subagent boundary

Each `codebase-fact-finder` is spawned in a fresh context window with
its question and an output path. `specs/_batch/prd.md` is on the
forbidden list — fact-finders cannot read requirement context, only
the codebase. This keeps research opinion-free (Horthy "hide the ticket
from research").

## Stage 2 — /plan

Planner self-verify + per-question human checkpoint walk.

Research is **not** part of this stage anymore — `/prd` ran the
codebase research. By the time `/plan` runs, both `prd.md` and
`research.md` are on disk.

**Owner**: MAIN spawns the `planner` subagent (single agent, opus
model). MAIN handles the per-Q walk in Phase 2.

**Inputs**:
- `specs/_batch/prd.md`, `specs/_batch/research.md` (from /prd)
- Alive masters: `ARCHITECTURE.md`, `CONTEXT.md`, `docs/adr/index.md`,
  `app_docs/codemap.md`
- Schema: `.claude/schemas/feature-list.schema.json`
- Active stack skill's `references/`

**Outputs**:
- `specs/_batch/feature-list.json` — validates against schema; primary
  handoff to /execution-loop
- `docs/adr/NNNN-<slug>.md` × M — `status: proposed`, written when the
  three-test gate passes; promoted to `accepted` at /finalize

**Phases**:

```
Phase 1   Planner self-verify (three-script trio, max 3 rounds)
Phase 2   Per-question checkpoint walk (one AskUserQuestion per
          open_question + per proposed ADR)
```

### Three-script trio (anti-rot guarantee)

| Script | Checks | Diagnostic when FAIL |
|---|---|---|
| `plan_validator.py` | JSON Schema 2020-12 + DAG cycles + missing depends_on + P1-cannot-depend-on-lower-priority | structural |
| `lift_capabilities.py` | duplicate IDs (feature/AC/Q), `decision_refs[]` resolve to existing files, `eval_anchors`/`must_not` uniqueness | semantic cross-reference |
| `plan_lint.py` | L10a (phase-named features rejected), L10b (UI-touching features need `l5_smoke_path`) | design discipline |

PASS/FAIL only — no WARN, no STRICT, no TODO. Any FAIL → planner reads
violations → fixes the **source design** (never patches around the
check) → retries (max 3 rounds).

### Three-test gate for ADRs

Before writing any ADR, all three must hold:

1. **Hard to reverse** — changing the decision later carries meaningful cost
2. **Surprising without context** — future readers will wonder "why this way?"
3. **Result of a real trade-off** — genuine alternatives existed and were rejected

Any one fails → not an ADR. Route the concern to `spec.business_rules`
or `spec.open_questions` instead. Without this gate, `docs/adr/`
accumulates noise — feature-local rules masquerading as architectural
decisions.

### open_question contract

`spec.open_questions[]` is the planner's **only** allowed escape for
"I don't know yet". Schema enforces:

- `resolution_kind ∈ {feature_local, architectural, glossary}` —
  three kinds only. **No `deferred`** (would leak debt across batches).
- `resolution` is non-empty at write time. Planner fills with their
  recommendation + rationale. The Phase 2 walk lets the user
  approve / edit / escalate.
- If planner cannot recommend, the batch scope is wrong: escalate, do
  not write null.

### Phase 2 per-Q walk

For every `open_question` (across all features) and every proposed ADR,
MAIN runs one `AskUserQuestion`.

For open_questions: **Approve** (keep planner's resolution) /
**Edit** (user provides corrected text) / **Escalate** (abort batch
back to /prd for re-scope).

For proposed ADRs: **Approve** (stays `proposed`, included in next
/finalize) / **Edit** (user revises body or title) / **Reject** (delete
the ADR file + clean `decision_refs[]`; planner must re-route the
concern).

After each Edit/Reject, MAIN re-runs the three-script trio before
continuing the walk. Any Escalate fires immediate batch abort.

**Skill**: `plan-workflow` + `planner-handbook` (auto-loaded by planner
agent's `skills:` frontmatter).

### Planner doctrine — `planner-handbook`

Loaded by the planner subagent at startup. Four references, read
on-demand at the relevant decision point (progressive disclosure):

| Decision point | Read |
|---|---|
| Module boundaries / interface vs implementation split | `references/deep-module.md` (Ousterhout depth_score + Pocock deletion test + 6 fake-deep anti-patterns) |
| Feature decomposition / vertical slice check | `references/vertical-slice.md` (Horthy + L10 lint signals) |
| Three-script trio interpretation | `references/self-verify-loop.md` |
| ADR identification / writing | `references/adr-lifecycle.md` (three-test gate + MADR + retroactive supersedes backfill) |

## Stage 3 — /execution-loop

Generator↔Evaluator round-based feature delivery.

**Status**: Pending implementation (T8 in `TODO.md`). Design intent:

- **Owner**: MAIN walks features in `depends_on` DAG order. Per
  feature, MAIN spawns `generator` + `evaluator` subagents (stack-aware
  via active stack skill delegation). Up to 3 rounds; PASS → DONE +
  next feature; 3 FAIL → BLOCKED.
- **Generator** reads the feature's spec + AC + active stack skill's
  `references/`; writes code + tests; emits self-verify report.
- **Evaluator** runs L1 (compile/lint), L2 (unit), L5 (smoke) from
  `feature.test_contract`; greps `eval_anchors`; asserts `must_not`;
  emits PASS/FAIL with violation list.
- Open architectural question: TDD-style (evaluator writes failing
  test first) vs post-hoc (generator writes both). Pocock's `tdd`
  skill is the closest analogue.

**Skill**: `harness-loop` (T8).

## Stage 4 — /finalize

Post-batch consolidation. Promote ADRs, lazy-create CONTEXT.md, regen
codemap, archive batch.

**Status**: Partial — `scripts/finalize_adr.py` and
`scripts/regen_codemap.py` are written and deterministic; the
orchestration skill is pending T9 rewrite (current `batch-gc/SKILL.md`
is heavily out-of-date).

**Phases** (designed):

```
Phase 1   Promote ADRs — finalize_adr.py: status proposed → accepted
                                        + retroactive supersedes
                                          backfill
                                        + regen index.md
Phase 2   Domain terms merge — scan prd.md H2 sections, extract Domain
          terms (draft) per R, dedupe across R, merge into CONTEXT.md.
          Lazy-create CONTEXT.md if missing (first batch in target).
Phase 3   Codemap regen — regen_codemap.py extracts barrel-file module
          docstrings; lazy-create app_docs/codemap.md if missing.
Phase 4   Archive — move specs/_batch/* to specs/completed/<slug>/.
```

Single human checkpoint: pre-archive sweep ("Approve archive?").

**Skill**: `batch-gc` (rewrite pending in T9; commands/finalize.md too).

### ADR promotion logic (`finalize_adr.py`, language-free)

Three deterministic passes — no LLM:

1. **Promote**: every `docs/adr/NNNN-*.md` with `status: proposed` and
   matching batch slug flips to `status: accepted`.
2. **Retroactive backfill**: for every newly-promoted ADR with
   `supersedes: [...]`, the predecessors' frontmatter gets
   `superseded_by: <new_id>` + `status: superseded`. **Body is never
   modified** — this is the only allowed mutation on an existing ADR.
3. **Index regen**: read all ADR frontmatter, partition by status,
   render topic chains via `tags`, write `docs/adr/index.md`.
   Deterministic — same ADR set → same index.

### Codemap regen (`regen_codemap.py`, stack-aware)

Walks the source tree for barrel files and extracts the first module
docstring from each. Default barrel patterns:

| Language | Barrel | Docstring |
|---|---|---|
| TypeScript | `index.{ts,js,tsx}` | top JSDoc / leading `//` |
| Python | `__init__.py` | top `"""..."""` |
| Rust | `mod.rs` / `lib.rs` | top `//!` inner doc |
| Go | `doc.go` | top `// Package foo ...` |
| Dart | `*.dart` containing `library;` | top `///` lib doc |

Active stack skill may extend or override patterns.

## Stack skill — the language plug-point

Each supported stack lives at `.claude/skills/<stack-name>/`:

```
<stack-name>/
  SKILL.md                  Stack identity + tools/MCP conventions
  references/               Vendored idiom library (one topic per file):
    routing.md, testing.md, modules.md, ...
    upstream.md             Provenance log — URL + revision + license
                            + fetched_at per vendored file (Mozilla
                            moz.yaml-style)
```

Bootstrapping is itself a skill: **`stack-skill-creator`**. It walks
the user through stack name + source (user-provided / web-search /
mixed) + scope (starter / comprehensive), vendors the docs, and
self-validates the new skill folder. It does **not** pre-bake
role-specific files (no `sink-module-doc.md` etc.) — downstream agents
define their own consumption contract; the creator only vendors raw
idioms.

The harness core (`prd-workflow`, `plan-workflow`, `planner-handbook`,
`harness-loop`, `batch-gc`) does not change when swapping stacks. This
is the **language-free core** invariant in `ARCHITECTURE.md`.

## Computational sensors — the deterministic spine

| Sensor | Input | Output | Runs at |
|---|---|---|---|
| `prd_lint.py` | `prd.md` | structural lint JSON (L01-L06) | /prd Phase 4 synth |
| `plan_validator.py` | `feature-list.json` | JSON Schema + DAG + ref check | /plan Phase 1 self-verify |
| `lift_capabilities.py` | `feature-list.json` | dupe IDs + decision_refs resolve | /plan Phase 1 self-verify |
| `plan_lint.py` | `feature-list.json` | design lint (L10a/L10b) | /plan Phase 1 self-verify |
| `finalize_adr.py` | `docs/adr/*.md` | promote + backfill + regen index | /finalize Phase 1 |
| `regen_codemap.py` | source tree | `app_docs/codemap.md` | /finalize Phase 3 |

All scripts are pure stdlib Python — no external deps. PASS/FAIL only.

## Worker prompt doctrine

Every worker prompt (subagent definitions in `.claude/agents/`,
orchestration skills in `.claude/skills/*-workflow/SKILL.md`) embeds
three sections:

1. **Mandatory before starting** — surface assumptions explicitly
   ("ASSUMPTIONS I'M MAKING: 1. ... 2. ... → Correct me now or I'll
   proceed.") + "do not silently fill in ambiguous requirements."

2. **Common Rationalizations** — per-agent table (5±2 rows). Each row
   is (a) the easy excuse this role is most likely to slip into,
   (b) why it's actually wrong. Catches self-deception that
   anti-patterns alone don't.

3. **Anti-patterns** — concrete behaviour shapes to avoid (separate
   from rationalizations: anti-patterns describe *what*, rationalizations
   describe *why agents drift toward what*).

The catalogue of all per-agent tables — and the universal rules every
prompt enforces (no `deferred`, no silent inference, no WARN, no
outsourcing without recommendation, lint is contract, vertical slices,
no fabricated provenance) — lives in `agent-prompt-doctrine.md` (this
directory). It is a maintainer SSoT, not a runtime input — each prompt
ships with its own embedded copy.

## Invariants (see ARCHITECTURE.md for the canonical list)

- **Codebase as SSoT** — alive docs supplement only what code cannot express.
- **Language-free core** — `.claude/skills/{prd-workflow, plan-workflow,
  planner-handbook, harness-loop, batch-gc}/` MUST NOT contain
  language- or framework-specific tokens.
- **Zero debt** — `/plan` produces no `risks` / `tech_debt` /
  `cross_r_risks` field. Every concern resolves to a proposed ADR (via
  three-test gate), an `open_question`, or a feature/AC. Schema's
  `additionalProperties: false` mechanically rejects rogue debt fields.
  No `deferred` punt.
- **ADR immutability** — accepted ADRs' bodies are never edited. To
  revise, write a new ADR with `supersedes: [old_id]`.
- **Vertical slices** — features cross every layer the requirement
  implies; phase-named features are rejected by `plan_lint.py L10a`.
- **Skill-shaped agent behaviour** — no agent code outside skills.
- **Single human checkpoint per stage** — exactly one `AskUserQuestion`
  gate per stage:
  - /prd: post-grill confirmation (Approve / Revise / Abort)
  - /plan: per-Q walk (the walk *is* the gate; each item is one
    `AskUserQuestion` but they are all part of the same checkpoint)
  - /execution-loop: per-round verdict (T8)
  - /finalize: pre-archive sweep (T9)

The four-stage harness draws on five external sources. Each row lists

### 1. Aleksey "matklad" Kladov — *ARCHITECTURE.md*

- <https://matklad.github.io/2021/02/06/ARCHITECTURE.md.html>

| Concept | Where in our harness |
|---|---|
| ARCHITECTURE.md as "absence of X" facts — the unique constraints and invariants of the system, not a tour | `ARCHITECTURE.md` shape — short, terse, lists invariants only. No bird's-eye onboarding mixed in. |

### 2. Birgitta Böckeler — *Harness engineering for coding agent users*

- <https://martinfowler.com/articles/harness-engineering.html>

| Concept | Where in our harness |
|---|---|

| Computational vs inferential controls | Computational = the six scripts. Inferential = grill-master interpretation, planner design judgement, evaluator semantic checks (T8). |
| "Whenever an issue happens multiple times, improve the feedforward and feedback controls" | Recurring agent drift → new row in agent-prompt-doctrine catalogue → synced into the affected prompts. |

### 4. Dexter Horthy — *Everything We Got Wrong About Research-Plan-Implement*

### What we considered and rejected

- **Osmani's full spec template** (Tech Stack / Commands / Project
  Structure / Code Style / Testing Strategy / Boundaries) as PRD format
  — rejected. Those are project-level / stack-level concerns; they live
  in `stack skill references/`, `ARCHITECTURE.md`, and target-project
  docs. PRD stays at what/why.
- **`docs/agents/` consumer-protocol layer** (Pocock convention) —
  rejected. Pocock externalises consumer rules so per-repo config can
  vary; we have agent-bound doctrine via per-agent prompts, not
  substrate-tunable.
- **Per-R subdirs** (`specs/R1/prd.md`, `specs/R2/prd.md`) — rejected
  in favour of single batch-level `prd.md` with H2 sections. With 1M
  context, sharding's token-saving rationale doesn't apply; planner
  must hold full batch context anyway for `depends_on` DAG design.
- **`deferred` resolution_kind** — rejected. Soft escape that
  manufactures cross-batch debt. Every question resolves in-batch or
  the scope is wrong.
- **WARN / STRICT / PASS_WITH_TODO lint severities** — rejected. Lint
  is PASS/FAIL. Middle states normalise drift.

## Maintainer-only files (this directory)

`docs/design/` is gan-harness-maintainer-internal. Target projects do
not inherit this directory:

- `gan-harness.md` — this file (current implementation reference)
- `agent-prompt-doctrine.md` — per-agent rationalization catalogue +
  universal rules SSoT
- `feature-list-spec.md` — frozen design notes for the
  feature-list.json contract (early-design rationale)

When `setup-gan-harness-skills` (T12) is built, it will copy the
`.claude/` tree but **not** `docs/design/`. Target projects build their
own `docs/adr/`, `CONTEXT.md`, and `app_docs/codemap.md` lazily as
their first batch lands.

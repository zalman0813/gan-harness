# `## Commands` — stack command contract

Every stack skill under `.claude/skills/<stack>/` MUST include a
`## Commands` markdown table in its own `SKILL.md`. This is the single
source of truth for the harness gate contract: the lint, typecheck, and
test commands that downstream agents and the pre-commit hook invoke.

Replaces the legacy `sensors.ini` file format. Rationale: LLM agents
(planner / generator / evaluator) read SKILL.md prose natively, so a
separate INI file forced double-bookkeeping. The pre-commit hook now
parses the markdown table via `.claude/scripts/parse_stack_commands.py`
— one small helper, one source of truth.

## Who consumes this table

1. **Pre-commit hook** at `<target>/.git/hooks/pre-commit` (installed
   by setup-gan-harness-skills). Calls
   `.claude/scripts/parse_stack_commands.py <stack> --key <key> --scope <files>`
   and executes the returned command string. Stages run lint.fix →
   lint.check → typecheck → test.unit → AC literal coverage.
2. **Evaluator** runs the same `lint.check` / `typecheck` / `test.unit`
   commands directly via Bash per its prompt (`evaluator.md` Process
   steps 2-3). The evaluator reads the table from SKILL.md as plain
   markdown — no parser needed on the LLM side.

## Required and optional keys

| Key | Status | What it runs |
|---|---|---|
| `lint.fix` | required | Stage 1 of pre-commit hook (<1s budget). Auto-fix in place. Evaluator does NOT run this — no in-place mutation during evaluation. |
| `lint.check` | required | Stage 2 of pre-commit hook AND L1 of evaluator (<5s budget). Read-only; fail loud. No `--fix`. |
| `typecheck` | required | Stage 2 of pre-commit hook AND L1 of evaluator. Strict mode is the project default — loosen only with cause. |
| `test.unit` | required | Unit / component runner. Pre-commit hook substitutes changed files; evaluator substitutes `verification_plan` paths. |
| `test.smoke` | optional | Smoke runner. Evaluator invokes when the sprint contract's `verification_plan` mentions a smoke step. Leave the row OUT entirely (or value empty) to skip. Pre-commit hook does NOT run smoke — post-commit only. |

## Table format

The parser is intentionally forgiving but expects:

- `## Commands` heading (exactly that text, H2 level).
- A `|<key>|<command>|` row per key. The header / separator rows are
  detected and skipped automatically.
- Each `<command>` cell may wrap the command in backticks (`` `cmd` ``);
  the parser strips them.
- Unknown keys in additional rows are silently ignored, so authors can
  add documentation rows without breaking the parser.

Example:

```markdown
## Commands

Harness gate contract. Pre-commit hook reads this via
`.claude/scripts/parse_stack_commands.py`. Required keys:
`lint.fix`, `lint.check`, `typecheck`, `test.unit`. Optional:
`test.smoke`. `{scope}` is substituted at invocation time.

| Key | Command |
|---|---|
| lint.fix | `ruff check --fix --silent {scope}` |
| lint.check | `ruff check {scope}` |
| typecheck | `mypy --strict {scope}` |
| test.unit | `pytest -x --tb=short {scope}` |
| test.smoke | `pytest --no-header {scope}` |
```

## `{scope}` placeholder

The harness substitutes this in the command string before execution:

| Caller | `{scope}` value |
|---|---|
| Pre-commit hook (`.git/hooks/pre-commit`) | Changed files from `git diff --name-only` (staged + unstaged + untracked, space-joined). |
| Evaluator | Per `verification_plan` step — typically a directory path for L2, a smoke-test path for L5, or the union of `spec.module_design[*].module_path` for L1. |

Always include `{scope}` in your command. NEVER hard-code paths like
`__tests__/` — that ignores the "changed files only" contract and runs
the whole suite every commit.

ALWAYS quote `{scope}` in the command string if your tool is whitespace-
sensitive (most modern lints handle space-joined multiple paths
correctly, but verify for your stack).

## Typecheck command MUST be production-faithful

Pick the typecheck command the **production deploy pipeline** would
run. If your stack has a "build" step that performs additional
validation beyond the bare type-checker (route contracts, schema
generation, codegen, etc.), prefer the build step.

Concrete trap (Next.js): `tsc --noEmit` alone misses Next.js's strict
route validation, because that validation is encoded in
`.next/types/**/*.ts` which is auto-generated by `next build`/`next dev`.
On a fresh checkout `.next/types/` doesn't exist, so tsc silently skips
the strict route checks. An earlier sprint can ship a route file with
an invalid named export, evaluator says PASS (because tsc was
incomplete), and a later sprint hits the failure when something in
between regenerates `.next/types/`. **Use `next build`** — it
regenerates `.next/types/` then runs tsc; production-faithful by
construction.

Cost-vs-correctness tradeoff: production-faithful is slower, but
catching debt at evaluator time costs vastly less than letting it leak
into a downstream sprint.

If the production-faithful command is too slow for the pre-commit hook,
you can ship two rows in the same table (the parser tolerates extra
rows with foreign keys it doesn't recognise). Don't preempt this
asymmetry — only split when speed becomes a measured problem.

## Empty values = skip

Omit an optional row entirely (or leave the value empty after the
pipe) to skip that step. The parser returns an empty string; callers
treat empty as "skip silently and log a SKIPPED note".

## Known limitation: dual-consumer scope semantics

The same `test.unit` row is consumed by **two callers with different
scope semantics**:

| Caller | What `{scope}` is substituted with | What the runner should do |
|---|---|---|
| Pre-commit hook | Changed files (mix of source + test files) | Run only the tests covering those changes |
| Evaluator | A directory path from `verification_plan` | Run all tests under that path |

Most test runners' positional CLI args are filename filters (substring
or glob match against test files). That works for the evaluator case
but is lossy for the pre-commit case — source files don't match any
test filename, so 0 tests run unless the runner has explicit
"tests covering this source file" support.

Stack-specific runners that handle the gen-side correctly:

- `vitest --related <files>` (uses Vite's module graph)
- `jest --findRelatedTests <files>` (uses Jest's coverage map)
- pytest: no built-in equivalent. Two practical options:
  1. **Accept gen-side weakness + strong evaluator gate** (the
     GAN-pattern default). Use `pytest -x --tb=short {scope}` with
     `--passWithNoTests`-equivalent behaviour via plugin if available.
     The evaluator's full path-scoped L2 sweep is the real safety net.
  2. **Adopt `pytest-testmon`** if the gen-side false-PASS becomes a
     real problem in your project.

NEVER hard-code `__tests__/` or `tests/` in place of `{scope}` — that
ignores the "changed files only" contract entirely and runs the whole
suite every commit.

## Self-validation

After emitting the table, stack-skill-creator validates **inline** —
it reads the just-written SKILL.md, locates the `## Commands` H2,
and confirms each required key has a row whose command contains the
`{scope}` placeholder. No external script call: the parser at
`.claude/scripts/parse_stack_commands.py` ships with the
setup-gan-harness-skills substrate copy, which may not yet be in the
target when a new stack skill is being created. Inline validation
sidesteps the chicken-and-egg.

For a post-setup target (substrate already copied), you can also run:

```
python .claude/scripts/parse_stack_commands.py <stack-name> --validate
```

which exits non-zero with a diagnostic if any required key is missing
or the table can't be parsed. That's a convenience, not a prerequisite.

## Why a markdown table (vs separate INI file)

`sensors.ini` was the old design. It was machine-readable but forced
authors to keep two artefacts in sync (the SKILL.md prose around it and
the INI file itself). LLM agents read the prose anyway; only the
pre-commit hook needed machine-readable structure. A small Python
parser (`parse_stack_commands.py`) gets us machine-readable parsing
without the duplicate-file overhead. Single source of truth, single
file format.
